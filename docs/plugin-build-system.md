# Plugin Build & Development

How Enclave plugins are structured, cloned, and built for local development.
This is a **build/dev** doc — for the runtime security model, the `context` API,
and permissions see [`plugin-development.md`](plugin-development.md). Today, shipping is
governed by `bundled-plugins.json`, described at the bottom.

## Where plugins live

Plugins are **separate git repos** (`mackerson/enclave-plugin-*`), **not**
tracked in this repo. `plugins/` is gitignored and holds **symlinks** to
sibling checkouts created by `scripts/setup-plugins.sh`:

```
../plugins/<name>/                  # the real repo (sibling checkout)
enclave/plugins/<name> -> ../plugins/<name>   # gitignored symlink
```

Which plugins ship in a packaged build is declared in `bundled-plugins.json`
(each entry has a `tier`: bundled / community / qa / example).

## First-time setup

```bash
git clone https://github.com/mackerson/enclave-ai.git
cd enclave-ai
yarn install          # deps + rebuild better-sqlite3 + build plugin UIs (postinstall)
yarn setup:plugins    # clone the plugin repos as siblings + symlink into plugins/
yarn dev
```

`yarn setup:plugins` is **required** for a full build (`yarn build` copies
bundled plugins into `dist/plugins`). The app will start in `yarn dev` without
them; no bundled plugins load. `yarn setup:plugins:pull` updates every plugin
checkout.

## Plugin UI build (build-on-install)

Plugin UI source lives in each plugin's `ui/src/`; the built bundle
(`ui/dist/`) is gitignored and generated by `scripts/build-plugins.js`:

- **`postinstall`** → builds all plugin UIs after `yarn install`
- **`prebuild`** → rebuilds before a production `yarn build`
- **`yarn build:plugins`** → manual full build; single plugin: `node scripts/build-plugins.js <name>`
- **Hot reload in dev** → `PluginWatcher` rebuilds + reloads a plugin on source changes, no restart

`build-plugins.js` discovers plugins that have both `package.json` and
`vite.config.ts`, runs `yarn install` if `node_modules/` is missing, then
`yarn build`. (Note: `predev` only rebuilds native modules — it does **not**
build plugin UIs; that happens at `postinstall` and via the watcher.)

## Plugin structure

```
plugins/my-plugin/
├── plugin.json          # Manifest — REQUIRES sandboxVersion + permissions
├── index.cjs            # Backend entry (runs in a Worker-thread sandbox)
├── package.json         # Build deps (vite, react, @vitejs/plugin-react)
├── vite.config.ts       # UI build config
└── ui/
    ├── src/index.tsx    # UI entry (exports named components)
    └── dist/index.js    # gitignored, generated
```

### Manifest (`plugin.json`)

```json
{
  "id": "com.enclave.my-plugin",
  "name": "My Plugin",
  "version": "1.0.0",
  "description": "…",
  "author": "…",
  "type": "ui",
  "entry": "index.cjs",
  "sandboxVersion": 1,
  "permissions": ["ui:views:register", "storage:write", "events:listen"],
  "ui": {
    "entry": "ui/dist/index.js",
    "components": { "MyComponent": "named" }
  }
}
```

- **`sandboxVersion: 1` is required** — plugins without it are skipped at load.
  Every plugin runs sandboxed in a Worker thread.
- **`permissions`** are grants enforced at runtime by `PermissionGate` (see the
  permissions table in [`plugin-development.md`](plugin-development.md)).
  Request only what you use — least privilege.

### Vite config (UI bundle)

Plugin UIs are ES-module libraries that **externalize React** — the host
provides it, so a plugin never bundles its own copy:

```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { resolve } from 'path';

export default defineConfig({
  plugins: [react()],
  build: {
    lib: {
      entry: resolve(__dirname, 'ui/src/index.tsx'),
      name: 'MyPlugin',
      formats: ['es'],
      fileName: () => 'index.js',
    },
    rollupOptions: {
      external: ['react', 'react-dom', 'react/jsx-runtime'],
      output: {
        paths: {
          'react': '/node_modules/react',
          'react-dom': '/node_modules/react-dom',
          'react/jsx-runtime': '/node_modules/react/jsx-runtime',
        },
      },
    },
    outDir: 'ui/dist',
    emptyOutDir: true,
    sourcemap: true,
  },
  resolve: { alias: { '@': resolve(__dirname, '../../src/renderer') } },
});
```

**Don't change the `/node_modules/react*` paths** — they are load-bearing. The
bundle emits bare-absolute imports like
`import { jsx } from "/node_modules/react/jsx-runtime"`, and the host resolves
them to shims that re-export `window.EnclaveAPI.React`:

- **dev** → the root Vite config serves the shims
- **production** → a privileged `moduleShim` scheme serves byte-identical shims
  (`src/main/protocols/moduleShim.ts`). This is the fix for the packaged-build
  404 that broke every plugin UI — the old inline-importmap approach
  was CSP-blocked.

Host-provided UI: plugin components pull React and shadcn/ui primitives off
`window.EnclaveAPI` (`.React`, `.UI.{Button, Input, Card, …}`) — see
`src/renderer/lib/plugin-api.ts` for the full surface.

## Distribution today · marketplace (not built)

- **Bundled**: `bundled-plugins.json` lists what ships in a packaged build;
  those are copied into `dist/plugins/`.
- **Load-path precedence** (`SandboxedPluginManager`): dev symlinks
  (`plugins/`) → user (`userData/plugins/`) → bundled (`dist/plugins/`).
- **Marketplace / install-from-registry**: **not built.** There is no install
  IPC and no registry — the marketplace plugin is a UI stub with mock data.
  Greenfield; the V1 design (first-party GitHub `registry.json` + assisted
  install) is planned — distribution today is by curated inclusion.
  Note: publishing a plugin to the registry requires a **built bundle** as a
  GitHub release asset (not source), so each plugin repo needs a release
  workflow — a V1 prerequisite.

## Troubleshooting

- **No plugins at all** → run `yarn setup:plugins` (symlinks missing).
- **Plugin not building** → needs `package.json` + `vite.config.ts` at its
  root; `node scripts/build-plugins.js <name>` prints the error. Clean:
  `rm -rf plugins/<name>/{ui/dist,node_modules} && yarn build:plugins`.
- **Plugin loads but UI is blank / `react` 404 in a packaged build** → check the
  `/node_modules/react*` externalization above and that `moduleShim` is
  registered (`main.ts`).
- **Plugin silently skipped at load** → missing `sandboxVersion: 1`.
